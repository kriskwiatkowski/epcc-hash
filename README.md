# EPCC Hash

## Running tests on native

```bash
cargo test
```

Architecture-specific assembly is replaced with an equivalent Rust
implementation on other targets, so the same tests run on any host
machine.

## Running tests on embedded (QEMU)

Install the Rust targets:

```bash
rustup target add thumbv7m-none-eabi thumbv8m.main-none-eabi \
  riscv32imac-unknown-none-elf
```

Build and run for each supported core:

**Cortex-M3**

```bash
cargo build -p demo-cortex-m3 --target thumbv7m-none-eabi
qemu-system-arm \
  -machine mps2-an385 \
  -cpu cortex-m3 \
  -nographic \
  -semihosting-config enable=on,target=native \
  -kernel target/thumbv7m-none-eabi/debug/cortex-m3-tests
```

**Cortex-M33**

```bash
cargo build -p demo-cortex-m33 --target thumbv8m.main-none-eabi
qemu-system-arm \
  -machine mps2-an521 \
  -cpu cortex-m33 \
  -nographic \
  -semihosting-config enable=on,target=native \
  -kernel target/thumbv8m.main-none-eabi/debug/cortex-m33-tests
```

Each test name is printed via semihosting and QEMU exits with success after
all tests pass.

## Running tests on RV32 (QEMU)

The RISC-V tests run under QEMU's Linux user-mode emulation, so they need
no board model or semihosting. `-cpu max` supplies the B extension, and
the runner is already configured in `.cargo/config.toml`:

```bash
RUSTFLAGS="-C target-feature=+zbb,+zbkb" cargo run -p qemu-riscv32 \
  --bin riscv32-tests --target riscv32imac-unknown-none-elf --release
```

Dropping the `RUSTFLAGS` builds the same tests against the portable
fallback, which is what a core without the B extension gets:

```bash
cargo run -p qemu-riscv32 --bin riscv32-tests \
  --target riscv32imac-unknown-none-elf --release
```

### What is accelerated, and when

| Target | `conv_*_bi` | `keccak_f1600` |
| --- | --- | --- |
| RV32 + Zbkb | `zip`/`unzip`/`pack` assembly, 6 instructions each | assembly |
| RV32 + Zbb only | portable Rust | assembly |
| RV32 baseline | portable Rust | portable Rust |

`zip`/`unzip` are RV32-only Zbkb instructions that perform exactly the
bit gather/scatter that interleaving needs, which is why a conversion
collapses from a ~30-instruction butterfly to six instructions.
`keccak_f1600` needs only `rori` and `andn`, which both Zbb and Zbkb
provide.

The permutation is generated by `keccak/gen/permutation_rv32.py` (no
third-party dependencies) and runs all 24 rounds in the bit-interleaved
domain, so each 64-bit lane rotation becomes one or two 32-bit `rori`
instructions. Measured with `qemu-riscv32 -one-insn-per-tb -d exec`, one
`keccak_f1600` call costs **10,587 instructions** against **56,100** for
the portable Rust built for the same target -- a 5.3x reduction. The
round body is 414 instructions (262 logical, 102 `lw`, 50 `sw`) and the
whole permutation is 1704 bytes of `.text` plus 192 bytes of round
constants.

Following Zhang et al., [*Optimized Software Implementation of Keccak,
Kyber, and Dilithium on RV{32,64}IM{B}{V}*](https://eprint.iacr.org/2024/1515)
(Sec 4.2), bit interleaving only pays off on RV32 once the B extension
supplies `rori`; on plain RV32I the encode/decode overhead outweighs it.
That is why the assembly targets Zbb and the baseline keeps the portable
path.

## Running benchmarks on embedded (QEMU)

Replace the binary name with the `-bench` variant, e.g. for Cortex-M33:

```bash
cargo build -p demo-cortex-m33 --target thumbv8m.main-none-eabi
qemu-system-arm \
  -machine mps2-an521 \
  -cpu cortex-m33 \
  -nographic \
  -semihosting-config enable=on,target=native \
  -kernel target/thumbv8m.main-none-eabi/debug/cortex-m33-bench
```

## Running on STM32H573I-DK

Requires [probe-rs](https://probe.rs/). Build and flash from the `runtime/stm32h573i-dk` directory:

```bash
cd runtime/stm32h573i-dk
```

**Tests**

```bash
cargo build --bin stm32h573i-dk-tests
probe-rs run --chip STM32H573IIKx ../../target/thumbv8m.main-none-eabi/debug/stm32h573i-dk-tests
```

**Benchmarks**

```bash
cargo build --bin stm32h573i-dk-bench
probe-rs run --chip STM32H573IIKx ../../target/thumbv8m.main-none-eabi/debug/stm32h573i-dk-bench
```

Output is printed over RTT. `probe-rs run` flashes the binary and attaches to RTT automatically.
